========================================================
 在 GitHub 上「在线」打包安卓 APK —— 保姆级教程
========================================================

为什么用这个办法
--------------------------------------------------------
你的电脑上没装 Docker，所以本地打不了 APK。
GitHub 提供免费的云端服务器（叫 GitHub Actions），
把代码传上去，它替你编译，打好的 APK 直接从网页下载。
你电脑上**什么都不用装**。

第一次大约 40~70 分钟（其中 30 分钟左右是等它下载 Android SDK/NDK，
约 2~3 GB）。以后再打包因为有缓存，只要 10~20 分钟。

★ 已经替你做到哪一步了（先看这里）
========================================================

代码已经推到你的仓库了，第一批打包也已经跑起来。
你只需要等它跑完，然后下载 APK —— 也就是只看「第四步」。

  你的仓库   https://github.com/lyaishy/fuckZHS

========================================================
第一步 · 把代码放到你自己的 GitHub 账号下
========================================================

先选一种做法。推荐【做法 A】。

── 做法 A：Fork（复制一份到你自己名下，最快）──
1. 浏览器打开  https://github.com/VermiIIi0n/fuckZHS
2. 右上角点【Fork】，再点【Create fork】
   现在你名下就有一份了：https://github.com/你的用户名/fuckZHS
3. 继续看第二步

── 做法 B：自己新建一个空仓库 ──
1. 浏览器打开  https://github.com/new
2. Repository name 随便起个名，比如  fuckZHS-android
3. 选【Public】（公开仓库的 Actions 额度无限、完全免费，强烈建议）
   ⚠ 不要勾 "Add a README file"
4. 点【Create repository】
   新建出来的仓库名就叫 fuckZHS-android
5. 继续看第二步


========================================================
第二步 · 把本机代码推上去
========================================================

双击本目录里的  push-to-github.bat
按提示填「你的 GitHub 用户名」和「仓库名」，回车即可。

第一次会弹出浏览器让你登录 GitHub，点【授权】就行。
（这个脚本只是执行 git 推送，不会碰你的密码。）

推成功的标志：最后看到一行
    [成功] 已推送。
如果失败，按屏幕提示把报错发我。


========================================================
第三步 · 让它开始打包
========================================================

1. 浏览器打开你的仓库页面
2. 点顶部的【Actions】标签
   如果第一次进来有黄色提示条，点
   【I understand my workflows, go ahead and enable them】
3. 左边列表里点  「在线打包安卓 APK」
4. 右边点【Run workflow】按钮
     - 架构选  arm64-v8a（2017 年之后的手机基本都能装）
     - 再点绿色的【Run workflow】
5. 页面会冒出一条任务，前面是黄色转圈的图标，点进去能看实时日志
6. 等它跑完。跑完会变成绿色对勾 ✓


========================================================
第四步 · 下载 APK 并安装
========================================================

1. 任务变成绿色 ✓ 之后，点进这次任务
2. 页面**拉到最下面**，有个【Artifacts】区域
3. 点  fuckZHS-APK-arm64-v8a  下载（下载下来是个 .zip）
4. 解压，里面就是 .apk 文件
5. 把 .apk 传到手机（微信传、数据线拷、网盘都行），点击安装
   手机可能提示「未知来源应用」，允许一下就好


========================================================
常见问题
========================================================

Q: 任务变成红叉 ✗ 了怎么办？
A: 点进去，看哪一步是红的。把红色那段日志截图发我，我来判断。

Q: 一定要建公开仓库吗？
A: 私有仓库也能用，但免费账号每月只有 2000 分钟 Actions 额度，
   一次打包就要 40~70 分钟，额度很不经用。公开仓库则完全不限量、不花钱。
   本项目本身也是从公开仓库 fork 来的，公开没有额外风险。

Q: 会不会把我的账号密码传上去？
A: 不会。下面这些文件已被 .gitignore 排除，推不上去：
     cookies.json        登录会话
     config.json         可能填过账号/密码/pushplus token
     gui_settings.json   本机设置
   而且工作流里还有一道「安全闸门」：一旦在仓库里发现这些文件，
   会让构建**直接失败**，绝不产出带凭据的 APK。

Q: 手机上的 App 会一直刷吗？
A: ⚠ 一个重要提醒：安卓系统的省电策略可能会在长时间后台运行时
   把 App 冻结。刷课时尽量让屏幕保持亮着、别切走太久。
   App 内已经申请了 WAKE_LOCK 防止息屏，但各品牌手机策略不同。

Q: 能不能改成每次推送代码就自动打包？
A: 能。已经配好了：改动  buildozer.spec  或那个工作流文件并推送时，
   会自动触发一次打包。平时手动点 Run workflow 也行。


========================================================
曾经踩过的坑（留个记录，以后你自己再看网络教程时会对得上）
========================================================

【坑 1】第一版工作流用了网上的 buildozer-action，第二次步骤就红叉

  现象：日志里
      Err:6 https://ppa.launchpadcontent.net/openjdk-r/ppa/ubuntu resolute Release
        404  Not Found
      Error: The repository '...resolute Release' does not have a Release file.
      ERROR: process "/bin/sh -c sudo apt update" ... exit code: 100
      ##[error]Docker build failed with exit code 1

  原因：那个 action 的 Dockerfile 是
      FROM ghcr.io/kivy/buildozer:latest
  也就是直接用 Kivy 官方镜像做底，然后在上面**又**加装了一遍 JDK，
  加装用的是 ubuntu 的 ppa:openjdk-r/ppa 这个软件源。
  但官方镜像的基础系统已经滚动到新版（代号 resolute），
  这个老 PPA 根本没有对应新版的文件，apt 一更新就报错，
  镜像都构建不出来 —— 所以任务在第 2 步就挂了，后面全被跳过。

  关键点：官方镜像本身**已经装好了 openjdk-17-jdk**，那一步纯属多余。

  处理：不再用那个第三方 action，直接调官方镜像，见工作流里
  「用官方 Kivy 镜像打包」那一步。官方镜像自带的 entrypoint.sh
  会把容器用户的 uid/gid 映射成宿主机的，并把 HOME 固定为 /home/user，
  所以我们只要挂两个目录：
      -v "$GITHUB_WORKSPACE":/home/user/hostcwd              项目本体
      -v "$GITHUB_WORKSPACE/.buildozer_global":/home/user/.buildozer
                                                         ↓ 这样 SDK/NDK 才能被缓存

【坑 2】python-for-android 的入口名改不了

  它永远执行应用目录下的 main.py。buildozer.spec 里的 android.entrypoint
  是 Java 类名，不是 Python 文件名，改它没用。
  所以本项目在 main.py 最顶部做了环境判断：安卓下直接拉起手机界面。

【坑 3】fucker.py 顶层 import 了 openai 和 tiktoken

  这俩包没进 requirements（tiktoken 在安卓上也没有现成配方），
  不处理的话 APK 装得上、一点「开始刷课」就崩。
  已改成"可选依赖 + 优雅降级"：视频刷课路径完全不受影响，
  只有 AI 课那条路会在缺失时给出明确提示。

【坑 4】.gitignore 里的 *.spec 会把 buildozer.spec 一起忽略掉

  那样 GitHub 上的云端构建拿不到配方文件，直接失败。
  已加白名单放行。

【坑 5】官方镜像的参数不要自己再写一遍 buildozer

  官方镜像启动脚本内部已经接好了 buildozer 这个可执行文件，
  你在 docker 命令最后写的参数，就是 buildozer 自己的子命令。
  写 `buildozer android debug` 会变成 `buildozer buildozer android debug`，
  报错：Unknown command/target buildozer
  正确写法就是 `android debug`。

【坑 6】requirements 里不要放没有配方的包

  buildozer 的 requirements 每一项都优先去找 python-for-android 的"配方"
  （配方 = 一套能在安卓上把它交叉编译出来的脚本）。
  找不到配方的包只能走 pip 装到安卓目标上，而带 C 扩展的包基本装不上。

  实测 p4a 有配方的：python3、kivy、openssl、pycryptodome
  实测 p4a 没有配方的：pillow、requests、urllib3、chardet、idna、certifi
  （后面这几个纯 Python 的不用你操心，Kivy 配方会自动把它们带上）

  另外**不要自己钉版本号**。p4a 官方 CI 每天在测的组合是
  CPython 3.14.2 + Kivy 2.3.1，这就是它的默认值；
  自己写 `python3==3.11.5,kivy==2.3.0` 反倒是一个没人验证过的组合。
  最终写的是：requirements = python3,kivy,openssl,pycryptodome

【坑 7】安卓上没有 PIL / tiktoken / openai，代码里不能当成必需

  本项目 utils.py 顶层 import 了 PIL，而 p4a 没有 pillow 配方。
  查下来 PIL 只用在"在电脑终端里用字符画显示二维码"，
  手机端二维码是画在 Kivy 界面上的，根本走不到 → 改成可选导入。

  更要命的是 mobile_core 里的依赖自检原来把 PIL / tiktoken / openai
  都算成"必需"，这三个在安卓上都不存在 —— 结果就是
  APK 装得上，但一打开就提示缺依赖、界面直接不能用。
  现在必需项只剩 requests 和 pycryptodome。
